# LearnWiz AI

LearnWiz AI is an AI-powered personal learning platform built to act like a
personal teacher rather than a generic chatbot. It helps learners understand a
topic, practice it, receive feedback, measure progress, and decide what to do
next.

## What the application does

LearnWiz AI turns an open-ended learning goal into a guided learning workflow:

```text
Learn → Understand → Practice → Feedback → Mastery → Recommendation
```

The platform combines conversational AI with structured learning experiences:

- **AI Tutor:** explanations, simpler explanations, examples, summaries,
  quizzes, and exercises.
- **Learn Mode:** AI-generated lessons follow a teaching sequence of concept,
  intuition, example, common mistakes, mini exercise, and understanding check.
- **Practice Mode:** learners solve questions, receive immediate explanations,
  and continue through a focused practice set.
- **Quiz Generator:** quizzes can be generated by topic, difficulty, question
  count, question type, and language, with server-side validation and scoring.
- **Documents:** authenticated users can upload PDFs, ask questions about them,
  request summaries, and use document-grounded RAG conversations.
- **Progress:** the dashboard surfaces learning history, topic progress, weak
  areas, and useful next actions instead of only vanity metrics.
- **Guest-first onboarding:** visitors can try the core learning loop before
  creating an account. Eligible guest data can be migrated on registration.
- **English and Turkish:** the UI, validation messages, learning flows, and AI
  response context support both `en` and `tr`.

## Why this project is interesting

The main product decision is to make AI serve a learning system. The application
does not treat every interaction as unstructured chat; it provides pedagogical
actions, validated structured content, practice feedback, usage limits, and a
clear next step for the learner.

The project also demonstrates production-oriented concerns such as:

- server-side authentication, authorization, and guest session migration;
- centralized entitlements and AI usage budgets;
- tenant-scoped document retrieval and protected R2 access;
- queue-based document processing and embeddings;
- localized product experiences and AI responses;
- webhook/idempotency-ready infrastructure boundaries;
- automated typecheck, lint, formatting, tests, builds, and staging deploys.

## Technology

- React 19, Vite 7, TypeScript strict mode
- Tailwind CSS 4 and accessible Radix/shadcn-style UI primitives
- React Router 7 with locale-aware English/Turkish routing
- Hono on Cloudflare Workers
- Cloudflare D1, KV, R2, Queues, Vectorize, and Workers AI
- pnpm workspaces, Vitest, and GitHub Actions

## Architecture

```text
Browser
  ↓
Cloudflare Worker (API + SPA assets)
  ├── D1: users, learning history, quizzes, conversations, usage
  ├── R2: uploaded documents
  ├── Queues: asynchronous document processing
  ├── Vectorize: document retrieval
  └── Workers AI: tutoring, lessons, quizzes, embeddings
```

The Worker remains the authority for identity, permissions, feature access,
usage limits, document ownership, and subscription state. Uploaded documents and
retrieved chunks are treated as untrusted content and cannot override system
rules or authorize actions.

## Environments

The public documentation intentionally exposes only the production/demo
endpoint. Development runs locally, while staging is used by CI for deployment
and smoke testing. Neither environment is required for a portfolio reviewer.

| Environment | Purpose                                      |
| ----------- | -------------------------------------------- |
| Local dev   | Local Vite + Wrangler development            |

## Quick start

Requirements: Node.js 24+, pnpm 11, and Wrangler for local Cloudflare
development.

```bash
pnpm install
pnpm dev        # web on :5173 and local Worker on :8787
```

## Useful commands

| Command                                    | Purpose                                   |
| ------------------------------------------ | ----------------------------------------- |
| `pnpm dev`                                 | Run the web app and local API together    |
| `pnpm typecheck`                           | Type-check all workspace packages         |
| `pnpm lint`                                | Run ESLint                                |
| `pnpm format:check`                        | Verify Prettier formatting                |
| `pnpm build`                               | Build the web bundle and Worker bundle    |
| `pnpm test`                                | Run frontend and Worker integration tests |
| `pnpm --filter @learwizai/api db:validate` | Validate D1 migrations locally            |

## Repository layout

```text
apps/web                 # React SPA, routing, UI, i18n, learning screens
workers/api              # Hono API Worker and Cloudflare integrations
packages/types           # Shared frontend/backend domain contracts
packages/validation      # Shared Zod validation schemas
packages/config          # Shared TypeScript configuration
db/migrations             # Versioned D1 migrations

```

## Deployment

- Pushes to `main` run validation and deploy staging through GitHub Actions.
- Production deployment is a deliberate manual workflow action.
- Cloudflare credentials belong only in GitHub Actions or Worker secrets; no
  credentials are committed to this public repository.
- Deployment and rollback details are documented in
  [docs/deployment.md](docs/deployment.md).
